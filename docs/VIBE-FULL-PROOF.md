# PhiVibe R14: full original Vibe proof obligation inventory

R13 mapped evidence to the first ten obligations shown in Vibe's Phase 8.4 `proof-brief`. R14 can use the **original `.vibe.proof.json` v1 file** generated by Vibe's `verify --write-proof` or `verify-proof` path. This original artifact stores the entire `obligations` array from Vibe's `VerificationResult`, including ID, category, description, source location, reported status, human-readable evidence and criticality.

The original file can contain **sensitive information**. PhiThon does not upload or store this full artifact and exports only obligation IDs, categories, reported status, criticality, selected test references and hashes. Do not commit private proof files to public GitHub repositories.

## Prepare the existing reports

Generate the following input artifacts using your existing tools:

- `contract.vibe` and Vibe Phase 8.4 `intent-brief.json`.
- The original Vibe `full.vibe.proof.json` from `vibec verify-proof`, then `proof-brief.json` **from that same original artifact** using `vibec proof-brief`.
- PhiThon `link.json` (R9) and `correspondence.json` (R10).
- PhiThon `behavior-report.json` (R11) and `property-report.json` (R12), generated against those exact source hashes.
- A reviewed `bindings.json` matching actual obligation IDs to existing test case IDs and/or 1-based property sample indices (R13 syntax). It can now refer to IDs **beyond the first ten**.

Example commands, with paths adjusted to your setup:

~~~sh
vibec verify-proof contract.vibe
vibec proof-brief contract.vibe.proof.json --report json --write-output proof-brief.json

npm run phi -- vibe-full-obligations \
  contract.vibe.proof.json \
  proof-brief.json correspondence.json link.json \
  intent-brief.json contract.vibe implementation.phi \
  behavior-report.json property-report.json bindings.json \
  --out full-evidence-ledger.json
~~~

All required R9–R12 reports must exist first. See ``docs/VIBE-BRIDGE.md`, ``docs/VIBE-BEHAVIOR.md` and ``docs/VIBE-PROPERTIES.md` for their generation steps.

## What is checked

- Full artifact's `artifact_version` and `schema_version` are `v1` (the actual Vibe proof contract).
- Exact claimed Vibe source SHA-256, IR SHA-256, emit target, reported verification backend and pass/blocked result match the separately supplied Vibe Phase 8.4 proof brief.
- Full `obligations` length equals Vibe proof brief's total count. Every obligation must have the seven fields emitted by Vibe's `VerificationObligation` dataclass. Obligation IDs must be nonempty, bounded and unique.
- The brief's **first ten projected rows**, including IDs, categories, statuses and criticality, must be identical and in the same order as Vibe's original first ten obligations.
- The R10 proof correspondence must still match the original .vibe / .phi sources and PhiPack module hashes; R11/R12 reports must still match that same source-link identity.
- Reviewed binding IDs may match **any obligation in the original inventory**, not only IDs in the short proof brief.

The original proof input is bounded to 2 MiB; up to 512 obligation rows may be mapped. Beyond those limits, R14 **refuses** rather than misrepresenting a truncated list as complete. The result is marked `OPERATOR_SELECTED_ORIGINAL_VIBE_V1_PROOF_UNATTESTED`.

The CLI creates the output file exclusively; it never overwrites a prior run. The R13 compact-brief `vibe-obligations` command remains supported unchanged.

## Report semantics

The new `phithon.vibe-full-obligation-evidence.v1` report includes:

- `obligationsInFullArtifact`: all rows actually present in the validated original proof array.
- `obligationsInCompactBrief`: first-ten rows in the separate compact brief.
- `obligationsMissingFromFullArtifact: 0`: input acceptance is contingent on the full array count matching the compact brief's declared total.
- `associatedSampledObligations`: number of full-inventory obligations to which the operator attached one or more selected reports. This is **not causal coverage**.
- `unresolvedSampledObligations`: all other obligations lacking exclusively reported matches or any chosen test evidence.

Rows independently preserve Vibe's reported obligation status and PhiThon's self-reported test-association state. For example, an obligation may be reported `satisfied` by Vibe while the selected PhiThon test reports `MISMATCH`. Both statuses are preserved.

**No change in trust level:** the complete imported original proof file could still be fabricated. Comparing hashes, counts and projections proves internal consistency **of supplied bytes**, not that Vibe executed, that the results are independently authenticated, or that PhiThon implements the entire intent contract. Sample coverage is not exhaustive equivalence.

The report always marks `fullInventoryAuthenticated:false`, `reportsIndependentlyAuthenticated:false`, `evidenceExecutionIndependentlyAttested:false`, `semanticCoverageEstablished:false`, `intentPreservationProven:false`, `crossLanguageEquivalenceVerified:false` and `modelRoutingApproved:false`.

**Ledger above ego: a complete inventory of claimed obligations is not a complete proof that they hold.**
